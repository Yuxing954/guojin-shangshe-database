# 日报经验与修正

## 原文覆盖必须与分析覆盖一致

本次名创优品不是没有原文：完整研究库中存在10月10日原文，但周一摘要已覆盖72小时，页面还读取旧24小时快照，造成摘要有内容、展开却报未保存。不能把“进入摘要”当作“正文已可阅读”。现在逐条从完整源库附原文到编辑稿，旧近期缓存不再是唯一依据。

## 列全与精选是两种需求

此前固定精选3—4条，并把其余段子放在标题清单中，未满足用户最新要求。当前“重点段子”统一列全部符合范围的新段子；纪要和音频单独登记。用源清单比对全部URL，不靠人工记条数，不在同一页面重复两份段子清单。

## 综合总结要先读全文

只抽首句或重复数据，无法解释变化。AI先通读完整原文，再分辨共同因素、品牌分化、统计期与基数、公司主业和转型事件。比如餐饮总客流与同店不同；名创总GMV与存量同店不同；飞亚达项目进度、东百业绩承诺不是已兑现利润；教育重申推荐不是盈利预测上调。综合判断需有这些事实支持，不能把单篇机构观点当作市场共识。

## 索引登记不等于已分析附件

调研纪要、录音仅列真实元数据、来源主题与未转写/仅标题登记状态，不下载、不读取附件、不编造内容摘要。研究报告与会议纪要分开标注，付费/临时直链不伪造。

## 检查必须覆盖真实故障

单纯JS语法和页面资源检查没有发现原文缺失。新增发布门槛：窗口一致、段子全部覆盖、来源对应、原文完整且与源库一致。添加周末原文无需依赖近期快照的回归验证，以及缺失正文阻止发布的验证。完成后回读线上编辑稿及前端读取路径，不能把提交成功视为内容完整。

“入库，非今日新发布”“不把项目规模当作需求增长”等是采集说明和写作自检，不是研究结论。正文改写为具体经营含义，日期、入库与核验信息保留于字段和凭证；假期错位说明其对同比的影响，计划用“拟”、预测用“预计”。先读全文、判断新增、归纳分化，再组织三点总结；旧数据只有支撑新比较才进入综合判断。原文保持不变。
