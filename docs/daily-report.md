# 国金商社日报：重点段子、行业观点与边际变化

用户最新目标：筛选值得读的重点段子，了解今日商社行业市场观点及边际变化。一页短文，约600—900字，不再展示大段数据列表、泛市场观点或独立新闻栏。每天北京时间16:00截点，周一从上周五16:00至周一16:00（72小时）为新增窗口，覆盖周六、周日全天及周一；其他日期仍为前24小时；来源只代表已读取样本，不能当作全市场共识。

周一须通读完整窗口的候选，先合并周末同事件和重复转发，再筛重点；周末重大变化优先，仍保持一页，不把窗口变长当作增加篇幅理由。

## 筛选

1. 从最新main隔离检出，读取AGENTS.md。保留已有原文、历史日报与数据。
2. 复用研究CSV、不可变增量manifest；`scripts/build_daily_report.py`读取商社和全市场两库，经`daily_scope.py`按主题保守初筛。不是按券商团队名或偶然提及某公司就认定相关。食品饮料（白酒、乳制品、调味品等）、医药、纯科技、造纸轻工不进入日报。餐饮、现制茶饮、商超、潮玩保留。电商行业不再纳入日报，包括平台电商、跨境电商及相关公司观点；阿里、京东、拼多多等不进入重点段子或行业判断。名创优品、泡泡玛特等零售/潮玩公司的海外经营仍保留，其线上渠道数据可作为公司证据，不单列电商行业。
3. 人工语义复核候选全文：优先新经营数据、经营趋势转折、盈利预期调整、政策及订单/新品催化；单纯重申推荐、旧观点转发和无新增信息降级。同一公司/事件合并，例如综合餐饮更新与单独海底捞更新只选一条。至多3—4条重点段子，不为凑数选无关内容。
4. 同行业跨来源对照，必要时回看前1—7天原文。区分经营变化（本期与上期）、预期变化（机构新旧预测）、新催化（新增事件）。只有同口径证据才写“上调/下调/超预期”。单篇新发文不是新共识；本期预测与上季度实际改善不是昨日盈利预测上调。无旧预测时说明无法判断预期修订，不编造“市场原先认为”。
5. 数据和新闻只作为观点证据，核验原文来源及发布时间；不再单列无关指标。不得以入库/抓取时间代替披露时间，不把新补录历史数据称为今日边际变化。新闻不能核验就不采用。

## 生成与审稿

运行 `python scripts/build_daily_report.py --date YYYY-MM-DD` 保留原始候选快照；最终页面只读 `data/daily/onepage/YYYY-MM-DD.json` 的schemaVersion=2编辑稿，没有新版编辑稿时显示未发布，不回退到机械截断原文。

结构：

```json
{
 "schemaVersion": 2,
 "date": "YYYY-MM-DD",
 "cutoff": "YYYY-MM-DDT16:00:00+08:00",
 "headline": "一句话今日主线",
 "focus": [{"title":"行业或公司｜重点","summary":"新信息及为何值得关注，保留预测/专家口径","sources":[{"source":"原文标题或机构","publishedAt":"带时区时间","url":"真实原文链接"}]}],
 "industries": [{"sector":"行业","view":"今日已读取观点的核心判断","changeType":"经营变化/预期变化/新催化/暂无新增","change":"相对哪一期发生什么变化；明确比较基准与限制","sources":[{"source":"原文标题或机构","publishedAt":"带时区时间","url":"真实原文链接"}]}],
 "quiet":"未取得重要新增观点的覆盖行业，限定为本次已读样本"
}
```

重点段子写具体事实/预测；行业表写主线和变化，避免两处重复数字。同行业观点分歧如实表达。出处小链接可点击，复制和下载均为同一页编辑稿。

验证：`python scripts/validate_daily_editorial.py --date YYYY-MM-DD`、`python -m unittest discover -s tests -p 'test_daily*.py'`、`node scripts/check-site.cjs`。确保比较期、范围、单位、事实与预测及来源匹配。

发布前fetch/rebase处理并发，仅提交日报相关文件，禁止强推和覆盖无关文件。通过已授权GitHub连接器写main；核验源码树、Pages成功、线上daily.html与当天onepage文件。保留原有每小时观点采集任务，日报自动任务负责筛选、编辑及发布，启动和部署可能晚于16:00。

## 综合判断占比（最新要求）

行业观点与边际变化应以综合分析为主，少复述段子：归纳跨公司共同点与分歧、辨别需求/价格/新品/开店/基数因素，解释对行业判断的意义，再写下一步验证指标。观点分析占正文一半以上，但不得为了增加判断而虚构证据。用“综合判断”标明编辑推断，事实、机构预测、专家口径分清，不把模型判断写成机构原话或市场共识。仍保留一页；当前有证据时可约900—1100字，不凑满。电商剔除仅作用于日报，不删除研究库原文、不改动其他任务。

## 新增内容清单（最新要求）

日报正文保持简洁，其后列完整的新段子、调研纪要、录音清单；研究报告单列“其他研究资料”，不得伪称纪要。不限重点段子3—4条；清单无条数上限。同一天同公司但不同内容保留，不同正文的同主题可合并，同文件按ID/名称去重。标题、真实发布时间、来源主题链接、未转写/仅标题状态必须保留。电商、食品饮料与纯科技继续剔除。

读取已入库研究CSV与data/research/library.json的元数据，运行 `python scripts/build_daily_resource_list.py --date YYYY-MM-DD`。该脚本不获取附件或录音，仅生成data/daily/resources/YYYY-MM-DD.json。周一同样使用上周五16:00起点；其他日期前24小时。手动补充今日清单可指定--cutoff带时区时间，并在页面显示与分析正文不同的清单截点。必须记录sourceThrough，避免将已入库覆盖冒充完整源站。

不要为此功能下载、读取或转写PDF/Word/录音，也不要调用下载接口。录音来源链接只打开来源主题，不能伪造直链。每天生成日报时同步重建清单并发布。

## 顶部每日总结（最新页面结构，替代行业观点区块）

用户已删除整个“行业观点与边际变化”区域；不要再次恢复该表格/逐行业解释区块。日报最上方新增“每日总结”，用一段约150—250字的综合判断概括当日主线、共同点和分化、最值得关注的变化及后续观察，避免泛泛说明。写入编辑稿dailySummary字符串；industries留空数组兼容历史校验。页面与复制/下载只显示每日总结、重点段子、新增内容清单。原文不修改，纪要与录音仍仅登记元数据不下载。对旧期没有dailySummary的编辑稿，可用headline作为摘要，不恢复旧行业区块。

## 全部新段子与原文完整性（最新要求）

“重点段子”现在列出窗口内全部符合商社范围的新段子，不再限定3—4条。以resources/日期.json的segments作为完整性基准；逐条AI阅读完整正文并写简短概括，将allSegmentsListed设为true。新增清单区域只保留纪要、录音、其他研究资料，避免新段子重复列两遍。

每日总结须先通读全部段子，再归纳共同主题、分化、边际变化及其含义；区分经营修复、公司转型事件、原有推荐逻辑重申，避免照抄关键词和数字。简短总结可150—350字，段子概括每条1—2句话，原文默认折叠阅读。不能为硬凑一页而漏掉新增段子。

生成编辑稿后运行 `python scripts/hydrate_daily_originals.py --date YYYY-MM-DD`：从完整研究库和增量中按来源URL附上全部原文originals，不依赖可能截断或覆盖不全的recent缓存。页面首先读取编辑稿内嵌全文；历史版本缺少内嵌原文时才尝试旧快照。每条提供阅读原文和真实来源入口，任何原文缺失必须在发布校验时失败，不能以“本期未保存”充当已完成。

validate_daily_editorial.py检查：所有segments恰好全部列入focus、每条原文存在、哈希正确且正文与完整源库完全相同。更新前读[日报经验与修正](daily-report-lessons.md)，发布后核验名创等周末来源与全部正文可读取；纪要和录音仍不下载。

## 默认收起与编号总结（最新展示要求）

每日总结写dailySummaryPoints三项数组，内容按①②③清晰分点；同时dailySummary以同三项编号换行组成，保证复制/下载一致。各点归纳不同主线，避免三段重复。所有段子摘要及原文均默认收起，用户点击段子标题后显示摘要，再可点击阅读原文。新增内容清单只显示调研纪要、录音、其他研究资料，不显示新段子；segments仍留在资源JSON里供完整性校验，不作为第二份段子列表展示。新版本发布须更新脚本和样式版本号，防旧页面缓存呈现过期结构。

## 单层段子与关键数据（最新要求）

段子仅一层details，默认收起；点击标题一次即显示摘要、完整原文和来源入口，不再嵌套“阅读原文”折叠层。每日总结①②③中尽可能保留能支持判断的重要数字：同比/环比、同店、门店数及净新增、交易金额、关键时间进度等；数字必须同时保留统计期、范围、单位与预测/承诺状态，不为堆数据省略口径。三点合计可约300—450字，保持清晰。关键数据与内嵌原文逐项核对，不新增未有来源的数据。

## 摘要默认可见（最新要求）

每条段子的标题、时间和摘要默认直接显示，点击标题/摘要后展开完整原文，原文默认收起；保持只有一层details。段子区域移除“查看来源”按钮和文字，真实来源URL继续保留在数据文件用于追溯与全文匹配，纪要/录音/研究资料清单的来源入口不受影响。不得把摘要再次藏进折叠内容。

## 复制日报链接

顶部“复制日报链接”复制所选日期的标题与固定日期页面URL，例如“2026年10月12日商社日报 https://yuxing954.github.io/guojin-shangshe-database/daily.html?date=2026-10-12”。分享链接只带date，不含缓存版本参数或锚点，防止后续打开切换成最新日报。原复制功能标为“复制正文”。

### 手机阅读（2026-10-12）
- 760px及以下隐藏共享导航，以返回数据库、日期选择和栏目锚点进入单页阅读。
- 摘要默认可见，点击标题或摘要展开、收起原文；不显示额外收起按钮和收起提示。
- 每日总结中的带单位数字加粗，不改写数据；正文以16px和充足行距阅读。
- 复制日报链接固定底部，预留安全区；选中日期决定复制标题与URL，保留正文复制及下载。

## 近期财报与行业重要数据（最新要求）
每日总结后增加“财报与数据”，页面、复制、下载保持一致。
- 财报检查覆盖公司未来14天预约披露与业绩发布日期，日期排序、未来7天优先。读取最新earnings-calendar.json和原始回执；已实际披露/取消的预约不再提醒。预约与实际区分，未知不猜，继续剔除电商及非覆盖行业。
- 行业数据覆盖酒店、旅游出行、免税、餐饮、零售、黄金珠宝、教育人服及相关消费宏观指标，检查最近3天发布或首次取得的重要新数据，不依赖段子是否提及。写统计期、范围、单位、同比/环比及口径、来源、发布日期；仅有入库时间标入库，不伪称发布日期，不把历史补录当今日变化。
- 用AI总结变化含义，重要发现融入①②③；假期错位、基数与预测属性明确。16点后手动追加须标实际入库/追加时间，不能混作原截点前发布。
- onepage新增earningsUpcoming数组（company/code/period/date/status/source/url/checkedAt/evidenceFile）、industryUpdates数组（title/period/summary/source/url/publishedAt或null/availableAt/evidenceFile）、monitoringCheckedAt。无有效条目不凑数；核验失败不能声称没有更新。历史日报保留当期快照，不加载今天的动态日历覆盖旧期。
- 发布前核验每条财报日期在当日至未来14天，排除已披露、取消、重复项目；行业数字与来源逐项相符。例行检查必须同时涵盖财报和行业数据，并记录无法访问的来源。
