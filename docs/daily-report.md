# 国金商社日报：重点段子、行业观点与边际变化

用户最新目标：筛选值得读的重点段子，了解今日商社行业市场观点及边际变化。一页短文，约600—900字，不再展示大段数据列表、泛市场观点或独立新闻栏。每天北京时间16:00截点，周一从上周五16:00至周一16:00（72小时）为新增窗口，覆盖周六、周日全天及周一；其他日期仍为前24小时；来源只代表已读取样本，不能当作全市场共识。

周一须通读完整窗口的候选，先合并周末同事件和重复转发，再筛重点；周末重大变化优先，仍保持一页，不把窗口变长当作增加篇幅理由。

## 筛选

1. 从最新main隔离检出，读取AGENTS.md。保留已有原文、历史日报与数据。
2. 复用研究CSV、不可变增量manifest；`scripts/build_daily_report.py`读取商社和全市场两库，经`daily_scope.py`按主题保守初筛。不是按券商团队名或偶然提及某公司就认定相关。食品饮料（白酒、乳制品、调味品等）、医药、纯科技、造纸轻工不进入日报。餐饮、现制茶饮、商超、潮玩保留。电商综合长文只提炼商贸经营相关部分，剔除云、算力等段落。
3. 人工语义复核候选全文：优先新经营数据、经营趋势转折、盈利预期调整、政策及订单/新品催化；单纯重申推荐、旧观点转发和无新增信息降级。同一公司/事件合并，例如综合餐饮更新与单独海底捞更新只选一条。至多3—4条重点段子，不为凑数选无关内容。
4. 同行业跨来源对照，必要时回看前1—7天原文。区分经营变化（本期与上期）、预期变化（机构新旧预测）、新催化（新增事件）。只有同口径证据才写“上调/下调/超预期”。单篇新发文不是新共识；本期预测与上季度实际改善不是昨日盈利预测上调。无旧预测时说明无法判断预期修订，不编造“市场原先认为”。
5. 数据和新闻只作为观点证据，核验原文来源及发布时间；不再单列无关指标。不得以入库/抓取时间代替披露时间，不把新补录历史数据称为今日边际变化。新闻不能核验就不采用。

## 生成与审稿

运行 `python scripts/build_daily_report.py --date YYYY-MM-DD` 保留原始候选快照；最终页面只读 `data/daily/onepage/YYYY-MM-DD.json` 的schemaVersion=2编辑稿，没有新版编辑稿时显示未发布，不回退到机械截断原文。

结构：

```json
{
 "schemaVersion": 2,
 "date": "YYYY-MM-DD",
 "cutoff": "YYYY-MM-DDT16:00:00+08:00",
 "headline": "一句话今日主线",
 "focus": [{"title":"行业或公司｜重点","summary":"新信息及为何值得关注，保留预测/专家口径","sources":[{"source":"原文标题或机构","publishedAt":"带时区时间","url":"真实原文链接"}]}],
 "industries": [{"sector":"行业","view":"今日已读取观点的核心判断","changeType":"经营变化/预期变化/新催化/暂无新增","change":"相对哪一期发生什么变化；明确比较基准与限制","sources":[{"source":"原文标题或机构","publishedAt":"带时区时间","url":"真实原文链接"}]}],
 "quiet":"未取得重要新增观点的覆盖行业，限定为本次已读样本"
}
```

重点段子写具体事实/预测；行业表写主线和变化，避免两处重复数字。同行业观点分歧如实表达。出处小链接可点击，复制和下载均为同一页编辑稿。

验证：`python scripts/validate_daily_editorial.py --date YYYY-MM-DD`、`python -m unittest discover -s tests -p 'test_daily*.py'`、`node scripts/check-site.cjs`。确保比较期、范围、单位、事实与预测及来源匹配。

发布前fetch/rebase处理并发，仅提交日报相关文件，禁止强推和覆盖无关文件。通过已授权GitHub连接器写main；核验源码树、Pages成功、线上daily.html与当天onepage文件。保留原有每小时观点采集任务，日报自动任务负责筛选、编辑及发布，启动和部署可能晚于16:00。
