# 酒店数据库 CSV 更新规则

## 数据源

历史上游为酒店之家 Excel 数据库，增量上游为网站正常“导出数据”功能生成的全国、城市、全国集团 Excel。历史工作簿只读取已保存值；网站导出覆盖相同主键，并保留导出窗口之外的历史记录。原始文件留在本地归档，不包含任何账号密码、Cookie或会话信息。

## 固定输出

| 文件 | 内容 | 主键 | 更新频率 |
|---|---|---|---|
| `hotel_industry_weekly.csv` | 全国、20城及各档次的 OCC、ADR、RevPAR、酒店数和房量 | `period_id + region + segment` | 每周 |
| `hotel_group_weekly.csv` | 华住、首旅如家、锦江中国区、亚朵经营数据 | `period_id + group` | 每周 |
| `hotel_supply_weekly.csv` | 各房量区间的酒店数、房量和连锁供给 | `period_id + region + room_band` | 每周 |
| `hotel_market_share_annual.csv` | 六大集团年度房间数市占率 | `year + group` | 每年 |

文件名保持稳定，不在文件名中加入日期。网页只读取上述固定路径。

## 更新流程

1. 读取已保存的历史Excel。年度市占率仅在年度源表已刷新并保存时更新；周度导出不刷新年度数据。
2. 在网站完成正常登录，分别点击“导出数据”：全国、全部20城、全国4集团；保存三个原始导出到同一个日期目录。
3. 执行 `python scripts/update_hotel_csv.py <历史xlsx路径> data --exports-dir <该日期导出目录>`。不指定导出目录时仍支持旧的两参数调用。
4. 检查程序输出行数，与上次版本比较。周度更新通常只增加最新周，不应大规模减少历史行。
5. 检查四张表主键无重复，`period_id` 使用 `YYYYWww`，日期使用 `YYYY-MM-DD`。
6. 检查 `occupancy_rate` 保持 0–1 小数，网页展示时再转为百分比；ADR、RevPAR 单位为元；市占率直接存百分数。
7. 将四张 CSV、来源核验记录、清单及首页酒店摘要一起提交；通过GitHub连接器发布并回读核验。

## 覆盖和修订

- 同一主键再次出现时，应以最新 Excel 中的记录覆盖旧值，不追加重复行。
- 历史数据被酒店之家修订时，以网站最新导出覆盖相同主键；导出只覆盖最近24周时，不能删除更早的历史数据。来源文件名、SHA256、每表新增和修订记录数见 `data/hotel-update-record.json`。
- 空值保持为空，不写成 0；0 只表示源数据明确为零。
- 最新周早于仓库现有最新周时停止发布，先确认是否选错 Excel 文件。

## 指标和同比口径

- 行业表 `adr` 优先采用“按入住日期统计”的房价，`revpar = occupancy_rate × adr`。缺失入住率时RevPAR保持空，不产生假零值。
- 集团表同时保留 `adr` 和 `stay_adr`；看板房价及价格/热度指数统一使用入住日期口径。热度指数不能替代入住率。
- 默认同比是去年同周号比较，入住率显示百分点变化，ADR/RevPAR/房量显示相对增速。看板及首页明确标注“未作节假日错期调整”。
- 同周号、相隔364天、同一假期相对位置是不同的基期规则。错期可比同比必须另建明确的期间映射，记录双方起止日期、假期/调休日结构和调整理由，不能按结果好坏选择基期。
- 节假日仅有周度数据时，不能把整周拆成精确日度假期数据。未补足去年历史的城市同比显示为空。量价分解需统一入住率、ADR和RevPAR的比较期间。
- 市占率仅提取“市占率”表最上方的六集团年度区块，在区块结束处停止；不得把下方的连锁化率写成集团份额。2025年六集团份额合计应为50.70%，不作归一化处理。
- 全国和城市房量均保留全部、15间及以上两套字段；计算同比时分子分母保持相同范围。

## 发布前校验

- 行业表必须同时包含“全国/全部”以及经济型、中档型、高档型、豪华型。
- `RevPAR` 与 `occupancy_rate × adr` 的差异应仅来自源表口径或舍入。
- 集团表必须包含华住、首旅如家、锦江酒店（中国区）和亚朵。
- 网页外层最新周期、四项 KPI、四个档次卡片均非空。
- 内层五个标签页可以切换，趋势图和集团表有数据。
