# 酒店数据库 CSV 更新规则

## 数据源

唯一上游文件为酒店之家 Excel 数据库。更新前先在 Excel 中完成外部数据刷新和公式计算并保存，转换程序只读取已保存的计算结果，不重新解释 Excel 公式。

## 固定输出

| 文件 | 内容 | 主键 | 更新频率 |
|---|---|---|---|
| `hotel_industry_weekly.csv` | 全国、上海及各档次的 OCC、ADR、RevPAR、酒店数和房量 | `period_id + region + segment` | 每周 |
| `hotel_group_weekly.csv` | 华住、首旅如家、锦江中国区、亚朵经营数据 | `period_id + group` | 每周 |
| `hotel_supply_weekly.csv` | 各房量区间的酒店数、房量和连锁供给 | `period_id + region + room_band` | 每周 |
| `hotel_market_share_annual.csv` | 六大集团年度房间数市占率 | `year + group` | 每年 |

文件名保持稳定，不在文件名中加入日期。网页只读取上述固定路径。

## 更新流程

1. 在 Excel 中刷新源数据、等待公式完成计算并保存。
2. 执行 `python scripts/update_hotel_csv.py <xlsx路径> <输出目录>`。
3. 检查程序输出行数，与上次版本比较。周度更新通常只增加最新周，不应大规模减少历史行。
4. 检查四张表主键无重复，`period_id` 使用 `YYYYWww`，日期使用 `YYYY-MM-DD`。
5. 检查 `occupancy_rate` 保持 0–1 小数，网页展示时再转为百分比；ADR、RevPAR 单位为元；市占率直接存百分数。
6. 将四张 CSV 一起提交。不要只更新其中一张后发布。

## 覆盖和修订

- 同一主键再次出现时，应以最新 Excel 中的记录覆盖旧值，不追加重复行。
- 历史数据被酒店之家修订时，保留修订后的值并在提交说明中写明涉及的期间。
- 空值保持为空，不写成 0；0 只表示源数据明确为零。
- 最新周早于仓库现有最新周时停止发布，先确认是否选错 Excel 文件。

## 发布前校验

- 行业表必须同时包含“全国/全部”以及经济型、中档型、高档型、豪华型。
- `RevPAR` 与 `occupancy_rate × adr` 的差异应仅来自源表口径或舍入。
- 集团表必须包含华住、首旅如家、锦江酒店（中国区）和亚朵。
- 网页外层最新周期、四项 KPI、四个档次卡片均非空。
- 内层五个标签页可以切换，趋势图和集团表有数据。
