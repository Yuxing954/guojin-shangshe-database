# 国金商社数据库｜网页编辑与外观验收规范

适用于行业、宏观、重点公司、行情、日历、观点纪要及其专题页。编辑已有页面时，以本次明确要求、目标页改前的实际显示和已确认的同类组件为依据。新建页面先选同板块、同用途的现有页面作母版。

## 一、动手前先确定改动边界

| 本次任务 | 编辑范围 | 对照对象 |
| --- | --- | --- |
| 更新数据或正文 | 走模块已有更新入口。保留组件、默认筛选、栏目顺序和样式；最新一期、长标题或新增系列可能改变排版时，检查对应区域。 | 同一页面、同一筛选下的新旧内容 |
| 调整单个板块 | 找到实际渲染该板块的页面、脚本和样式。沿用相邻同类组件，新增规则限定到该板块。 | 本板块改前画面和相邻组件 |
| 调整共享组件 | 查出引用该样式的入口和匹配该规则的组件。统一改组件所属文件，检查使用它的不同页面类型。 | 目标页面及其他实际使用该组件的代表页 |
| 新建专题 | 从同类页面复用导航、内容容器、筛选、图表、表格和状态提示；按专题数据安排内容顺序。 | 所选母版；同时支持单独打开和行业页嵌入的专题，两种入口均检查 |

凡涉及外观，先在浏览器按 100% 缩放记录目标网址、窗口宽度、页签和筛选值，截取桌面和手机的目标区域。改版先写明预期变化，例如“新增一个地区筛选，手机可换行，图表与下方表格仍左对齐”。这样复核时能判断哪些变化属于本次任务。

## 二、找到真正控制外观的位置

1. 从目标 HTML 读取样式表顺序，检查页面是否带有工作台或紧凑看板标记。在浏览器“计算样式”中点开异常元素的字号、宽度、间距等属性，找到获胜规则。属性由脚本渲染的，也查该模块的渲染函数。
2. 公共基础样式见 `scripts/site.css`。工作台组件见 `scripts/workspace-design.css`，紧凑看板密度见 `scripts/dashboard-compact.css`，行业筛选栏见 `scripts/dashboard-toolbar.css`。专题网格与业务布局在对应模块维护。每次先核实目标页实际加载了哪些文件。
3. 旧版《全站显示规范》可查设计意图，但其中“主标题 30px”和“site-polish.css 最后加载”不能直接套用到现行工作台。工作台已有 22px 主标题规则；紧凑看板已有 28px 主读数、36px 行高规则。这些数值用于查偏差，编辑时复用组件或变量，手机和嵌入模式分别核对。
4. 单页问题修在最小生效范围。避免给所有按钮、表格、卡片或标题加覆盖，避免为压过旧规则而在页面末尾再叠一份样式。共享资源有版本参数时，同步更新实际引用入口并检查普通刷新后的效果。

## 三、组件按以下标准验收

| 对象 | 合格表现 |
| --- | --- |
| 导航与标题 | 沿用现有导航、选中态和标题层级。单独打开只有一套主导航，嵌入行业页后主导航不重复。正文、筛选栏、卡片与图表沿用同一内容边界。 |
| 筛选与按钮 | 标签与对应控件靠在一起，顺序与操作一致。窄屏可整组换行，选中项清楚，键盘焦点可见。普通筛选控件沿用现有 40px 规则，内部分段按钮沿用组件自己的尺寸。 |
| KPI 卡片 | 同组标题、主数值、单位和期间对齐。宏观核心指标在同一宽度下等宽等高；有无预测、数据缺失或读取失败时，主数值位置稳定，状态仍完整可读。 |
| 图表 | 标题说明指标，轴或表头给单位；图例颜色与线条一一对应。在首期、末期及多序列最密集处检查标签、图例和提示框。窄屏可减少刻度密度，保留数据点。新交互图沿用 SiteCharts，切换指标后重新绑定；鼠标、手机点按和键盘均能读到对应期间的真实值。 |
| 表格 | 同列数字对齐，同指标的小数位、单位一致。长公司名可换行，负号、百分号和单位完整。宽表在自己的容器内横向滚动，整页左右边界保持稳定。禁止通过隐藏整页溢出掩盖截断。 |
| 文案与状态 | 用标题、表头、短标签交代指标和单位。保留来源、下载和必要口径，详细覆盖与计算说明归入 data-notes.html。加载中、无匹配结果、数据缺失和读取失败分别呈现，失败可重试。研究原文按原文保留。 |

**数据格式也属于验收范围。** 紧凑期间标签沿用 `26Q3`、`26M9`、`26W41`。统计期间、发布日期、行情时点分别标识。同比增速可写“同比+7.4%”，入住率由 70% 升至 72% 写“提升2个百分点”。缺失显示“—”，真实零值显示 0。筛选之后，图题、期间、单位、提示框、表格和导出范围应对应同一组数据。

## 四、提交前怎样查

- **单页外观改动**：在 1440px 桌面和 390px 手机按改前条件并排查看截图，再过 1024px、768px 两个中间宽度，重点看侧栏切换、筛选换行和表格溢出。至少实际操作一次受影响的筛选、页签、图表或弹窗；用一个最容易撑破布局的真实样本复核，如最长公司名或最多序列。
- **共享样式改动**：在上述检查基础上，对每类受影响入口选一页复核同一组件。若改宏观核心卡片，检查中国、美国两组，并覆盖 1920、1440、1024、768、390px。若改行业专题，同时核对独立页及行业页嵌入视图。
- **现有检查**：新增页面运行 `node scripts/check-site.cjs`；共享布局运行 `node tests/site-unification.browser.cjs`，可用环境变量 `SITE_SCREENSHOT_DIR` 留存桌面和手机截图。变更图表交互时运行 `node tests/site-charts.browser.cjs`；模块专有功能按其维护文档运行。自动检查后仍要目视核对目标区域的对齐、留白和可读性。
- **通过条件**：所有差异均能对应本次需求；无新增遮挡、截断、整页横向滚动、空白占位或无响应控件。发现差异，定位原因、修正并重拍同一状态。仅更新数据且展示结构未动时，按模块流程检查实际变化的内容即可。
- **交付记录**：用一行写明“改了哪个入口和组件｜验证了哪些宽度、状态和关联页｜结果及仍未核验项”。发布任务在部署完成后，用正式网址普通刷新，复核同一入口和状态；本地检查、正式站核验和既有无关失败分别记录。
