# 财报日历
入口：`earnings.html`，一级导航“财报日历”。使用现有 SiteData、manifest 与 GitHub Pages。公司身份复用全站唯一目录`data/coverage-companies.json`；当前已查询Choice财报的32家作为财报覆盖池。行情观察池新增公司不自动声称已经核验其财报日期；后续Choice查询可按目录代码扩展，不维护重复公司名单。

## 默认与操作
- 默认“最近”列表，按北京时间当天滚动。上方按日期升序显示未来30天预计披露；下方每家公司只选最近已实际披露的一期，按实际日期倒序，先显示10家，可展开全部。每行并列最近财报、实际日期与下一次已公布安排。
- 最近一期由真实披露日期决定，不按月份猜测当前报告期；跨年不清空历史，不默认选择尚无数据的新年度。下一次由尚未实际披露且预计日期不早于当天的记录决定；已过预约日独立标注，不能自动变成已披露。未找到下一次安排时显示待公布，不猜报告期或日期。
- 首屏只有公司/代码搜索、行业、最近/月/周。月默认当前月，周默认本周；上一/下一及“今天”用于浏览日期。市场、只看关注、完整历史和导出收进“更多”。原报告期、财报类型、公告类别、状态和提醒天数下拉不再占首屏。
- 手机最近列表按公司纵向展示，实际披露日和下次日期直接可见。详情支持Esc，关注存当前浏览器，搜索及视图状态可通过URL恢复。旧版含period参数的链接不会锁定旧季度。
- CSV导出筛选内的已收录记录与来源；ICS导出各公司下一次有日期的安排，提前3天提醒。页面显示未来30天安排，日历可包含30天以后的下一次日期。没有日期的公司不生成事件。
- 预约/预计、实际披露、公告发布日期分别展示。Choice“定期报告实际更新日期”不是实际披露日期，严禁替代。Choice预计字段不一律声称为交易所已确认预约，界面以“预计”标注。
- 公司历史、预约变更、公告原文、字段来源、核验依据和个人旧记录放详情。个人记录独立标记未经核验，不能覆盖公共日期。预告/快报独立归档，不能计为正式财报披露。

## Choice MCP 数据入口
主快照：`data/earnings-calendar.json`，version=2，primarySource=choice-mcp。所有活动日期记录的sourceId必须为choice-mcp；旧交易所/旧快照日期不作为缺失Choice日期的自动替代。
当前环境使用已连接的东方财富/Choice妙想MCP：
- A股：mx_ashare_finance_data；实际100000000007105，预计100000000007104。
- 港股及美股：mx_hk_finance_data / mx_us_finance_data；实际100000000051385，预计100000000051384。
- 按公司、报告期查询两个准确的披露日期字段，保留返回列名、证券代码、报告期、Choice跳转及指标标识。查询尽量只含日期指标，不混入财务数值或新闻。
- `data/earnings-choice-receipts.json`为本次MCP返回的日期表和查询回执，不包含配置、凭证、认证头。每条记录另保存可独立核验的原始行、列、值、查询、工具、时间与Choice指标链接；后续部分更新不会使旧证据依赖被覆盖的回执索引。

本次2026-10-10更新：32家最近财报日期均有Choice返回；84条真实日期记录；未来30天21家A股有预计安排，美股亚朵下一次为30天之外，10家港股未取得下一次安排。港股三季报查询返回的2025年数据仍是2025年历史，绝不改成2026年。不以历史日历推算今年，不把旧报告期返回当成最新预约。港/美股报告期标签沿用Choice字段，不擅自把中报映射为完整中期报告刊发日。

公告原文及公告日期保留此前核验的同代码/同报告期上交所、披露易文件，并单独标注announcementSourceId；Choice实际日期和该文件发布日期可以不同。暂无原文显示待补，公告日期缺失显示待公布。Choice客户端EM链接保留在证据中，不伪装成HTTP公告原文。

## 更新流程
1. 从最新main读取覆盖池，调用上述MCP查询当前已披露报告期与下一次安排。用本次真实返回保存新的回执，格式version=1、provider=choice-mcp、envelopes（query/tool/checkedAt/data）；不要手写日期或将失败响应改为成功。
2. 运行 `node scripts/import-earnings-choice.cjs data/earnings-choice-receipts.json`。导入器支持Choice三种矩阵布局，逐格核对证券、字段指标ID、报告截止期、日期、原始证据；不采用数据库实际更新日期。返回2025列就登记2025，不按请求文字强制改期。
3. 非法日期、未来实际披露日、缺失Choice指标证据、同一字段冲突、空结果终止。部分更新保留已有Choice历史；未查询字段保留先前Choice值及证据，已存在实际披露日不能被空值抹掉。保留字段变更及已核验原文，成功后原子替换。
4. 核对最新一期、下一次日期及缺失；运行逻辑和浏览器检查，PR检查通过后按既有main/GitHub Pages流程发布并回读线上数据。当前是维护者触发的MCP刷新，网页读取保存快照；不声称实时或云端自动同步。

`data/earnings-calendar-archive.json`保留上一版74条来源历史；在公司详情按需加载，只列主Choice数据未覆盖的报告/预告/快报。原9月11日快照的来源与核验时间保持原值。旧`update-earnings-calendar.cjs`仍供归档解析测试，其CLI拒绝覆盖Choice主快照。
