# 财报季工作台

入口：`earnings.html`，主页左侧“财报季工作台”。独立 HTML/CSS/JS，不重新序列化主页的内嵌研究看板。

## 数据及存储

- 覆盖池通过 `data-manifest.json` 中的 `valuation` 数据集读取。
- 公开披露日期来自 `data/earnings-snapshot.json`。`records` 只收录与目标报告期、目标证券匹配且返回了有效日期的数据；`evidence` 保留妙想 MCP 对应字段的原始表格。
- 当前快照：2026-09-11 查询的 2026 中报定期报告实际披露日期。港股字段可能对应业绩公告，不能混用其他财务报表的公告日期。
- 携程、亚朵本次未返回目标报告期的有效日期，界面留空待核实。其他报告期同样不推算日期，不使用法定截止日充当预约日期。
- 页面读取已发布快照，不在浏览器内调用 MCP；没有自动同步能力，也不包含 MCP 凭证。
- 更新时使用 `mx_ashare_finance_data` / `mx_hk_finance_data` / `mx_us_finance_data` 查询同一报告期。检查实际返回的列名、代码、报告期后再更新快照及 `updatedAt`，不能依问句假设返回结果正确。
- 会议可通过 `mx_finance_search_notice` 核对后登记，区分新闻、公告和不同年份，不把未核实会议写入日历。
- 个人负责人、日期校正、会议、问题及进度按“报告期 + 证券代码”保存在 `localStorage` 的 `sinolink-earnings-v1`。不同报告期隔离；只对当前浏览器有效，不是多人协作后台。
- JSON 备份包含全部报告期的个人记录。恢复时验证字段，合并记录，同键替换。CSV 导出当前筛选结果；ICS 导出其披露、会议、未完成任务的截止日期。
- 会议输入按北京时间处理，ICS 转为 UTC；披露和截止日期为全天事件。

## 检查

运行 `node scripts/earnings.test.cjs` 检查快照与覆盖池对应、记录保存、报告期隔离、筛选、备份恢复、日期及日历时区。

发布应将页面、样式、脚本、快照及主页入口放在同一提交，避免入口先出现而资源尚未就绪。
