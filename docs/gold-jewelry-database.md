## 2. 研究框架：不把黄金珠宝数据库做成金价行情页

建议按“原料价格—品牌报价—行业需求—公司经营—产品结构”建设。每个模块回答不同问题，不能仅凭金价变化推断珠宝公司的利润。

| 层级 | 核心字段 | 首选来源与补充来源 | 建议节奏 / 优先级 |
| --- | --- | --- | --- |
| 原料价格 | Au99.99收盘/加权均价、上海金基准、国际金价、汇率；原币原单位 | 交易所原始发布；妙想/Choice作为检索与补充渠道 | 交易日 / P0 |

## 3. 必须固定的口径

**价格。** 国内外市场、人民币/港币/美元、克/两/金衡盎司分别存储；原始数值不覆盖。饰品挂牌价、投资金条、回收价、换购价和一口价不得混合。城市、纯度、税或工费未披露时保留null，不推定为免费或已含。第三方转引不升级为品牌原始披露。

**价差。** 本版只考虑同日、同市场、同币种单位、Au99.99收盘参考。品牌须原始来源核验，且纯度、税费口径明确，才输出参考差。报价时点仍可能不同，输出必须标明“同日收盘参考差”，不是同步成交价差，更不是毛利率。缺少2026-10-08基准时不使用9月30日收盘前向填充。

**需求。** 国家统计局的限额以上金银珠宝类金额指标，不等于全行业黄金销量；销售金额增长与实物吨数变化分开。1—2月合并口径不得拆成两个人造月度数。中国黄金协会与世界黄金协会的统计范围不直接拼接。季度累计保留原披露，单季推算另记为计算值并记录输入；不能用累计同比冒充单季同比。

**公司。** 财政年度标签之外必须保存期间起止日、币种、合并范围、直营/加盟、地区；批发收入与终端零售收入、同店金额与同店销量、公司毛利与渠道利润不能混为同一指标。公司只披露期末店数时，不虚构新开/关店拆分。

**定价产品。** 老铺黄金等定价产品采用固定SKU篮子；同SKU规格、重量、材质、渠道、促销条件一致才比较。新品/旧款退出、规格变化另记事件，不直接当涨价。一口价除以克重只能作为产品单位重量售价观察，不能并入品牌足金挂牌价。

## 4. 数据结构与可追溯性

现阶段沿用CSV/JSON静态发布，不引入数据库服务、服务器密钥或新的前端框架。随着历史积累，可在私有采集端增加SQLite/DuckDB，导出经审定JSON/CSV供原站使用。

当前文件：

- `data/gold-jewelry/observations.json`：品牌维表、来源表、品牌报价、交易所基准、缺口说明。
- `data/gold-jewelry/mx-queries.json`：五类只读查数任务。
- `scripts/gold-jewelry-model.js`：校验、参考价差与安全CSV导出。
- `scripts/gold-jewelry.js`：来源可见的页面渲染、筛选及既有数据复用。
- `update/gold_jewelry.py`：只读API备用采集、上金所解析、私有原始响应归档、审阅批次导入。

报价记录包含：`id, brandId, quoteDate, quoteTime, market, city, currency, unit, product, priceBasis, purity, includesLabor, includesTax, price, sourceId, verification`。

来源记录包含：`id, name, provider, kind, url, capturedDate, publishedAt, captureMethod, rawArchive, note`。首批没有保存原始字节，因此`rawArchive=null`；不能伪造SHA256或截图凭证。未来HTTP采集器保存真实响应后才生成SHA256，原始文件保留在仓库以外。

后续公司经营事实表建议增加：`companyId, metricId, periodStart, periodEnd, fiscalPeriod, basis, region, channel, currency, unit, value, sourceId, reportName, page, publishedAt, capturedAt, quality, revisionId`。同源同口径冲突由导入器阻断，审阅后另记修订；当前脚本不自动裁决新旧版本。

## 5. 妙想接入方式

仓库已有 `data/industry/miaoxiang-2026-10-07.json`。本版继续通过既有归一化行业快照展示，保留来源状态，不把读取缓存标记为当日实时查询。

曾使用的第三方桥接项目：`jm12138/eastmoney-mx-finance-mcp-server`。其代码中 `mx_data(toolQuery)` 对应 `/query`，`mx_search(query)` 对应 `/news-search`，请求头使用 `apikey`。本版Python命令是同类接口的**API备用采集方式**，不是已经连通MCP的证明。

在有授权的Work/本地环境中优先调用已配置MCP的只读工具。需先验证当前可用工具、身份/权限和响应字段，再执行查询计划。只启用金融查数与资讯检索，不调用自选股修改或模拟交易。API备用脚本只从环境变量`MX_APIKEY`读取认证；不要把密钥粘贴进仓库、前端代码、研究报告或日志。

查询拆成五类：限额以上金银珠宝零售；黄金消费量结构；Au99.99价格；公司财务；公司经营公告。每次需要指标代码、单位、期间、来源URL及发布日期。返回自然语言总结不直接升格为事实表；先检查结构化表与原始披露。脚本只归档未经映射的响应，不盲目自动写库。

## 6. 本地/Work使用

以下命令在完整仓库根目录执行；增量包本身不含原站公共脚本和历史数据。Python使用标准库；Node用于测试，不是网站运行时依赖。

```bash
# 质量检查与连接状态（不显示密钥值）
python update/gold_jewelry.py validate
python update/gold_jewelry.py status
node --test tests/gold-jewelry.test.js
python -m unittest discover -s tests -p 'test_gold_jewelry.py' -v

# 已在受控环境配置MX_APIKEY之后；原始响应默认保存到仓库外
python update/gold_jewelry.py mx-fetch --query-id jewelry_retail --start 2026-01-01 --as-of 2026-10-08
python update/gold_jewelry.py mx-fetch --query-id company_operations --company 周大福 --start 2026-01-01 --as-of 2026-10-08

# 指定真实交易日；先生成待审阅批次，不覆盖正式表
python update/gold_jewelry.py fetch-sge --date 2026-09-30 --as-of 2026-10-08 --out /tmp/sge-review.json
# Windows将 /tmp/sge-review.json 换成仓库外的可写路径
python update/gold_jewelry.py import-batch --input /tmp/reviewed-batch.json

# 在完整仓库中预览
python -m http.server 8000
# 浏览 gold-jewelry.html
```

同一批次重复导入不新增重复行；同ID不同内容、同来源同口径重复观测均报错。来源修订需审阅处理，不覆盖旧值。HTTP采集遇到无数据、表头变化、非唯一记录、重定向或API业务错误时停止，不插值、不把空值写成0。
