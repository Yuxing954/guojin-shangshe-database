# 出海与餐饮数据建设

核对批次：2026-10-10（北京时间）。展示名称为“出海”“黄金”，行业键仍为 `overseas`、`gold`，公司原始分类键和旧链接不变，研究题名不改写。

## 字段及计算

- `metrics`：稳定指标ID、单位、频率、范围、可选固定期间口径。`points`：期间起止、`basis`、值、同比/环比、来源、精度与状态。
- `companyObservations`：公司、指标、期间、口径、单位、范围与来源，不把人民币/美元、人均/每单、存量/净增合并成同一可比指标。
- `sources`：原始机构、转载/平台状态、URL、发布日期、采集/核对日期、PDF页码或表定位、哈希。旧整理值保留旧状态；未知字段不补造。
- 同比/环比优先保存发布者公布的可比口径增速。限上企业样本逐年调整，不能通过金额简单回算替代官方同比。
- 海底捞同店销售同比 = `(2026H1同店销售 / 2025H1同店销售 - 1) × 100`；安克境外占比 = `同期间境外收入 / 合并收入 × 100`。记录输入与公式，均为计算值。
- 美元百万转亿美元除100；人民币元转亿元除1e8；万亿展示值按字符串单位换算。CPI指数不会未经明确口径转换为增速。
- 金额配同比须同源同期间，Choice不同指标行只在完整回复哈希及采集日期一致时配对。历史曲线断开缺期和跨年累计，不推算缺月。

## 增量更新

1. 默认离线：`python scripts/update_sector_data.py`。只合并已审核证据、已有历史和官方消费观测，验证全部结果后原子替换各JSON。重复执行不改变内容或“最近核对”日期。
2. Choice MCP不在GitHub Actions中自动认证。在有授权的MCP会话查询，完整回复保存在非公开缓存后执行：

   `python scripts/update_sector_data.py --choice-receipts .cache/sector-receipts --retrieved-at YYYY-MM-DD --cutoff YYYY-MM-DD`

   精确匹配指标、单位、频率及机构，拒绝不匹配行；同一期增量合并，优先官方、官方转载、平台、旧整理，再按发布/采集日期。拒绝条目保存在 `choice-history.json.rejected`，原始完整回复和认证配置不提交。
3. 美国官方表：`python scripts/update_sector_data.py --refresh-us`。抓取公开SA/NSA表并严格验证列、期间、单位和发布批次。新批次需要先核对公告并更新批次规则；页面变化、空表、未来期间或请求失败都保留历史，不把未知新批次静默标成旧发布日期。
4. 公司及海关新披露追加/修订 `data/sectors/reviewed.json`；每项要求来源、定位、单位、范围及期间，计算值须带输入。公司新一期记录不得覆盖旧一期。
5. `python scripts/build_home_snapshot.py --industry-only` 仅刷新首页行业摘要，保留当前研究列表；完整站点构建会继续读取原研究库。
6. 既有每日工作流增加离线增量整理，并保留专题历史；不宣称自动调用Choice或代表上游已刷新。`update-status.json`独立记录失败状态，前台显示保留历史的提示。
