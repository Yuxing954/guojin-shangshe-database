# 观点纪要的维护方式

## 日常只登记原件

1. 管理者把 Word、PDF 或录音放入 OneDrive“国金商社资料库/00_待入库”，保留原文件名，不用填表或分行业。
2. 告诉助手“更新观点纪要”。助手通过已连接的 OneDrive 读取文件元数据与有效分享权限，登记标题、文件日期和下载入口，再更新网站。上传本身不会自动触发发布。

默认不下载原件、不提取正文、不转写录音、不生成逐份摘要、跟踪项或财务指标，也不逐份做口径运算。资料先可查找、可下载，需要研究某一份时再单独处理。行业分类可后补，未分类资料仍可通过文件名搜索。

客户页面是名称、日期、板块、下载组成的紧凑列表，每页20份。已有摘要保留为可选入口，已有口径疑点与日期冲突不会因界面精简而被标记为已核对。待获取的线索收进“日期与其他筛选”。市场观点摘要及商社观点原文继续独立维护。

## 唯一日常入口

`python scripts/sync_research_library.py --batch-dir <私有批次目录>`

默认模式只需要连接器读取结果 `sharing-receipts.json`。每项含 metadata、对应文件的 driveId/itemId，以及回读有效权限得到的 permission。它们由助手整理，不要求用户手填。无需批次 catalog、source-texts、摘要、依据定位或异常计算表。

登记器只比较云端返回的文件身份、大小、版本和可用哈希，不读取原件字节；哈希缺失时以云端版本绑定文件，明确记录 verificationMethod=provider_metadata_version，不冒充字节级校验。相同文件重复登记不会新建条目，也不会重写已有摘要与审阅状态。原件变化不沿用旧摘要。

客户下载必须持有真实、未过期的 anonymous/view 权限，roles=read，prevents_download=false。脚本验证回执和稳定的 OneDrive 分享地址，不创建分享权限，不把本地标记当成用户授权；公开范围仍需按用户已明确授权的文件配置。失败的批次不修改网站。

公开索引只保存展示字段与可用客户链接；云端项目ID、ETag原值、所有者地址、权限ID、认证信息及完整回执留在网站外的私有目录。临时签名下载地址不能写入索引。管理目录与待入库文件夹保持私有。

## 按需深入整理

只有明确需要摘要时，才使用 `--with-summaries` 切换到已有的整理流程：私有 catalog、提取文本和可核对的原文依据。PDF读取保留真实页码；录音须先取得真实转写并保留时间段，不能从标题推断内容。机器初稿不自动升级为已核对事实或市场共识。

原有259份知识星球PDF/录音仍是待获取索引。首批22份Word原件已开放持链接查看和下载，无需登录；其中8份摘要保留9项校核问题，2份会议日期冲突仍待核对。原件及完整提取文本不上传公开GitHub仓库。

客户点击“下载”进入 OneDrive。Word网页版：文件→创建副本→下载副本；OneDrive预览页：⋯→下载。稳定分享页支持查看与保存，不提供站内即时二进制下载。
